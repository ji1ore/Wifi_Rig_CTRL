1. 概要

Wifi RIG CTRLは、AndroidデバイスをRaspberry Pi経由（またはCI-V Wi-Fi / Bluetooth直結）でICOMトランシーバーに接続し、周波数・モード・PTT・デジタルモードをリモートコントロールするアプリです。

主な機能
• 周波数 / モード / フィルター / PTTコントロール（IC-705、IC-7300、IC-9700 等）
• FT8 / FT4 デコード・送信・自動QSOシーケンス（Pi経由またはCI-Vオンデバイスデコード）
• Raspberry Pi経由のCWキーヤー
• APRSモニタリング（Pi経由）
• ワンタップでPiソフトウェアを更新
アプリはローカルWi-Fiネットワーク経由でPiと通信します。接続前にAndroidとPiが同じネットワークにあることを確認してください。

4. FT8画面

FT8画面ではリアルタイムのデコード表示とTX操作が行えます。

デコードエンジン
• Piモード: PiがバックグラウンドでWSJT-Xを実行し、SSEでリアルタイム配信
• CI-V WiFiモード: AndroidでFT8ローカルデコード（Pi不要）
• CI-V BTハイブリッド: BTでCI-Vコントロール + RS-BA1 WiFi音声でオンデバイスFT8デコード

4.1 デコード・メッセージ一覧

デコードされたFT8/FT4メッセージが一覧表示されます。各行には以下の情報が含まれます：

列説明
Hzデコードされた信号の音声周波数
SNR信号対雑音比（dB）
メッセージデコードされたFT8メッセージテキスト
UTCそのピリオドのUTC時刻（HH:mm:ss）

メッセージはUTC時刻順に表示されます。TX送信エントリは赤、受信メッセージは白またはグリーンで表示されます。

行をタップすると、そのメッセージのDXコールサインがTXフィールドにコピーされ、すばやく返信できます。

4.2 TX操作

TXフィールドにメッセージを入力し、TXボタンを長押しして送信します。

ボタン説明
TX（長押し）CQ AUTOモード開始。CQを繰り返し送信し、返信局と自動QSOを行います。
CQ AUTO（短押し）CQ AUTOを停止してOFFに戻ります。
AUTO（短押し）QSO AUTOを停止してOFFに戻ります。
CQ短押し: CQメッセージをTXフィールドに入力。長押し: コールサイン・グリッドロケーターを設定。
CLRTXフィールドをクリアして送信待ちをキャンセル
AUTO E / AUTO O自動TX周期の切り替え — Even（0/30秒）またはOdd（15/45秒）
FT8ピリオド: Even = UTC 0秒と30秒。Odd = UTC 15秒と45秒。DX局がEvenで送信しているときは自分はOddに設定します（逆も同様）。

4.3 自動QSOシーケンス

自動QSO機能で標準的なFT8交信を自動化します（グリッド交換 → 信号レポート → RR73 → 73）。

  1. デコード一覧のCQ行をタップしてDX局を選択し、TXフィールドにメッセージを入力します。
  2. TX周期（Even / Odd）を自分の送信スロットに合わせて設定します。
  3. 必要に応じて開始ステップを選択します（Step1=最初の呼出、Step2=信号レポート送信、Step3=RR73送信）。
  4. QSOを開始をタップして自動シーケンスを開始します。
自動QSOのステップ:
Step1: 「DX MY_CALL MY_GRID」を送信（最初の呼出）
Step2: 「DX MY_CALL R±XX」を送信（信号レポート）
Step3: 「DX MY_CALL RR73」を送信（確認）
73またはRR73を受信するとQSO完了。

ステータスバーに現在のステップと次のTX周期までのカウントダウンが表示されます。

相手局が信号レポートを送ってこない限り（グリッドロケーターなど不正なレポートを受信しても）次のステップへは進みません。相手局の応答を待ち続けます。

4.4 CQ AUTOモード

TXボタンを長押しするとCQ AUTO（オレンジ）になります。このモードではCQを自動的に繰り返し送信し、返信してきた局と自動的にQSOシーケンスを進め、73交換後に再びCQに戻ります。

CQ AUTOのフロー:
1. CQを自動送信（設定したEven/Odd周期）
2. 自局コールサインへの返信を検出したら自動QSO開始
3. 信号レポート交換 → RR73 → 73送信
4. QSO完了後、自動的にCQへ戻る（繰り返し）
  • 複数の局から同時に返信があった場合は、最初に検出された局とQSOします。
  • 短押しでCQ AUTOを停止できます。
  • TXフィールドには常にCQメッセージが表示されます。QSO中に変更しても、QSO完了後は元のCQメッセージに戻ります。
CQ AUTOを開始する前に、CQボタンで「CQ コールサイン グリッド」形式のメッセージをTXフィールドに入力してください。コールサイン未設定の場合は先にCQボタン長押しで設定します。

5. CWキーヤー

CW画面では、PiのオーディオをトランシーバーのキーまたはMICジャックに接続してモールス符号を送信できます。

操作説明
速度（WPM）1分あたりの語数（Words Per Minute）でコード速度を設定
テキストフィールド送信するテキストを入力。送信をタップして送信。
メモリーボタン（M1〜M6）よく使うフレーズを保存・呼び出し。長押しで現在のテキストを保存。

CWキーヤーはPiモードが必要です。BT CI-Vを使用する場合は、RS-BA1 Audio Hostを設定するか、リグをCWモードに切り替えてPTTを使用してください。

8. ヒント・トラブルシューティング

Piに接続できない

  • AndroidとPiが同じWi-Fiネットワークに接続されているか確認してください。
  • IPアドレス・ホスト名を確認してください。不明な場合は🔍スキャンを使用します。
  • Pi側のAPIが起動しているか確認します: sudo systemctl status hamcat
  • ポート8210がファイアウォールでブロックされていないか確認してください。

FT8がデコードされない

  • リグがUSB-DまたはFT8モードになっており、音声がPiに正しく入力されているか確認してください。
  • Syncをタップしてアプリの時刻をPiのUTC時刻に同期します。
  • デコード深度を上げてください（D:3を推奨）。

TX周期のタイミング

FT8ピリオドは15秒ごとに繰り返されます：
• Even（偶数）: UTC 0秒と30秒
• Odd（奇数）: UTC 15秒と45秒

DX局がEvenで送信している場合、自分はOddに設定します（逆も同様）。

INSTALL_FAILED_UPDATE_INCOMPATIBLE

新しいビルドをインストールする際にこのエラーが表示された場合、署名鍵が変更されています。先にアプリをアンインストール（設定 → アプリ → Wifi RIG CTRL → アンインストール）してから再インストールしてください。

mDNSが解決できない

  • 接続画面でUSE mDNSスイッチを有効にしてください。
  • Androidデバイスによっては「Wi-Fiのみ」モードで.localホスト名を解決できる場合があります。
  • 代替手段として、PiのIPアドレスを直接入力してください。

QSOが途中で止まる / 自動で進まない

  • FT8では相手局が正しいフォーマット（±数字の信号レポート）を送信してきた場合のみ次のステップに進みます。
  • 相手局がグリッドロケーターを再送している場合は、こちらのステップは進みません（仕様通りの動作です）。
  • 状況に応じてQSOダイアログを開き直し、開始ステップを手動で設定してください。
