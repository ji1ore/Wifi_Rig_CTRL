1. Overview

WifiRigCTRL connects your iPhone or iPad to an ICOM transceiver via a Raspberry Pi server (or direct CI-V Wi-Fi / Bluetooth) to provide remote control of frequency, mode, PTT, and digital modes.

Key features
• Frequency / mode / filter / PTT control (IC-705, IC-7300, IC-9700, etc.)
• FT8 / FT4 decode, transmit, and automatic QSO sequence (Pi server-side or CI-V local decode)
• CW keyer via Raspberry Pi
• APRS monitoring (via Pi)
• USB-NCM CW keyer relay (AtomS3 Lite connected via USB)
• One-tap Pi software update
The app communicates with the Pi over your local Wi-Fi network. Make sure both devices are on the same network before connecting.

4. FT8 Screen

The FT8 screen provides real-time decode display and TX control.

Decode engine
• Pi mode: Pi runs WSJT-X in the background; results are streamed via SSE
• CI-V mode: ft8lib runs on-device on iPhone (no Pi required)

4.3 Auto QSO Sequence

The Auto QSO feature automates a standard FT8 contact (CQ → Report → RRR → 73).

  1. Tap a decoded CQ row to select the DX station and fill in the TX field.
  2. Set TX Period (Even / Odd) to match your transmit slot.
  3. Optionally set Start step (Step1 = first call, Step2 = send report, Step3 = send RR73).
  4. Tap Start QSO to begin the automated sequence.
Auto QSO steps:
Step1: Send "DX DE MYCALL GRID" (first call)
Step2: Send "DX DE MYCALL +xx" (signal report)
Step3: Send "DX DE MYCALL RR73" (acknowledgment)
QSO complete when 73 or RR73 is confirmed.
The sequence only advances when the DX station sends a correctly formatted signal report. It will wait indefinitely if the DX station resends a grid locator instead.

4.4 CQ AUTO Mode

Long-press the TX button to enter CQ AUTO mode. The app repeatedly transmits CQ and automatically runs the QSO sequence with any station that replies, then returns to CQ after each contact.

Before starting CQ AUTO, tap the CQ button to fill a "CQ CALLSIGN GRID" message. Long-press CQ to update your callsign and grid locator first.

8. Tips & Troubleshooting

Cannot connect to Pi

  • Confirm both iPhone/iPad and Pi are on the same Wi-Fi network.
  • Check the IP address / hostname. Use 🔍 scan if unsure.
  • Verify the Pi API is running: sudo systemctl status hamcat
  • Check that port 8210 is not blocked by a firewall.

FT8 not decoding

  • Confirm the rig is in USB-D or FT8 mode with the audio routed correctly.
  • Tap Sync to synchronize the app clock with UTC time.
  • Increase decode depth (D:3 is recommended).
  • In Pi mode, verify jt9 (wsjtx package) is installed on the Pi.

TX period timing

FT8 periods repeat every 15 seconds:
• Even: UTC 0s and 30s
• Odd: UTC 15s and 45s

If the DX station is transmitting on Even periods, set your AUTO to Odd (and vice versa).

mDNS not resolving

  • Enable the USE mDNS switch on the Connect screen.
  • As a fallback, enter the Pi's IP address directly.

USB-NCM CW keyer not detected

  • Confirm the AtomS3 Lite has the Client firmware installed.
  • After connecting via USB, wait a few seconds for iOS to acquire the 192.168.7.x interface.
  • In the USB Relay settings screen, tap Start and confirm the Atom Client status shows "Detected" in green.
  • Verify that cw_bridge_ncm.py is installed on the Pi (Admin → Update Pi installs it automatically).

Auto QSO stalls / does not advance

  • FT8 only advances to the next step when the DX station sends a correctly formatted signal report (±nn format).
  • If the DX station keeps resending a grid locator, the app waits — this is the correct behavior per the FT8 protocol.
  • Re-open the QSO dialog and manually set the start step if needed.
